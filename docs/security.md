# Security operations

Run the verifier from a trusted checkout, supply protected policy/image/paths, and keep the candidate checkout separate. The sample policy requires a known task ID and mandatory syntax and unittest checks. Do not run unreviewed Dockerfiles or scripts as setup. Grant Docker privileges only to the trusted verifier job; candidate code receives no daemon socket or credentials by default. Avoid mounting host secrets, SSH agents, home directories, or unrestricted volumes. Review the Docker daemon's own privileges and favor a remote microVM for hostile code.

Keep report/ledger paths in access-controlled storage outside the candidate; the Docker runner mounts neither the report directory nor the ledger. The trusted harness emits a nonce-bound result on stdout; the supervisor captures it, rejects missing/duplicate/malformed records, checks it against the observed process exit code, and hashes the canonical record. The runner caps retained stdout/stderr to 64 KiB each and the structured record to 64 KiB, but arbitrary secret text in the retained portion is **not automatically redacted**. Run with no real credentials. Retain and externally checkpoint ledger hashes if deletion detection matters. Restrict policy and image modifications to a trusted owner; policy path separation alone is not authorization. Hooks are convenience workflow enforcement only; require a protected CI check for merge control.

Known gaps: candidate tests remain untrusted and may attempt to spoof stdout/nonce records or modify their own test suite. The nonce is visible in argv and is only correlation, not authentication; direct `os.write` injection is detected by strict full-channel parsing but not cryptographically prevented. The trusted acceptance suite is now separate and required by the sample policy, but it still runs in the same container and imports candidate code, so it is an independent assertion baseline rather than complete semantic isolation. Image tag is not immutable, Docker isolation is untested here, cleanup after daemon faults is untested, and ledger tail truncation is invisible without an external anchor. Fail closed rather than treating these limitations as solved.
