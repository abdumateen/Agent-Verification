# Implemented architecture

`cli.py` and `mcp_server.py` call `verifier.verify`; neither computes a verdict independently. `contracts` validates claims, `policy` checks trusted JSON and its fingerprint, and `snapshots` copies eligible source and computes deterministic path/content SHA-256. The Python adapter parses AST and emits definite syntax errors and optional stub warnings without executing candidate code. `sandbox.run_checks` launches policy-controlled argv in separate Docker containers; its trusted test harness writes JSON counts. `policy.decide` evaluates mandatory results. `audit` stores started/completed events with ordered hash links in SQLite; `reports` verifies a report digest against a completed event.

The sample policy at `policies/python.json` uses one Python syntax command and one unittest command. The claim cannot change the check list. Exclusions and a manifest are recorded in reports. `INCONCLUSIVE` is returned for missing Docker, timeout, corrupt report, changed workspace/policy/snapshot, or missing mandatory evidence; definite syntax or test failure is `REJECTED`. `NEEDS_REVIEW` is available through policy. `CHECKING` and `UNVERIFIED` are conceptual states, not durable status transitions in this version.

MCP SDK 2.1.1 provides six stdio tools: validate configured claim, request verification, status, report, recent runs and audit integrity. Its paths are supplied by the host environment, not MCP call arguments. The opt-in pre-commit hook and CI wrapper call the same CLI. A bypass-resistant deployment requires protected policy/image, a trusted verifier job, and branch protection outside this repository.
