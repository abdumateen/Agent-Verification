# Threat model

## Assets and actors
Assets: developer workstation, credentials, Docker daemon, trusted policy/image, source snapshot, test evidence, audit ledger and report. The agent controls candidate source, claim text and possibly its own test suite; the administrator controls verifier process, policy, image and evidence location. The model does not assume an agent exposes hidden reasoning or memory.

## Boundaries and controls
Claim validation rejects malformed task IDs and unsafe relative changed-file paths. Policy is outside candidate and task-allowlisted; its hash is rechecked after execution. Snapshot copies regular files and rejects symlinks, excludes common secret/cache entries, records manifest and verifies post-run workspace fingerprint. Docker options specify non-root UID, read-only snapshot/root, no network, dropped caps, no-new-privileges, PID/CPU/memory/time and tmpfs limits; the candidate never receives the Docker socket or host credentials intentionally. A timeout attempts `docker rm -f` using a container ID file outside the candidate mount. Logs and structured reports have bounded reads. The ledger detects modification of retained rows; reports carry a digest in the ledger.

The previous implementation mounted a host temp directory at `/results` with mode `0777`; candidate tests could write or replace `report.json`, and the verifier would accept structurally valid fabricated counts. The corrected boundary does not mount the verifier's report, ledger, policy, or final-report paths into the container. Candidate Python `print()` output is redirected to diagnostics; direct `os.write(1, ...)` can bypass that redirection, so the supervisor requires exactly one full-channel nonce record and rejects extra/duplicate/malformed output. The nonce is visible in the harness argv and is not confidential. Tests explicitly assert that `/results` is absent from Docker argv and that fake stdout/control attempts cannot produce trusted passing evidence. A mandatory acceptance suite is separately stored, fingerprinted, mounted read-only, and executed by the trusted harness.

## Residual threats
Docker is not microVM isolation. Candidate tests can still alter candidate source/tests before or during execution, print arbitrary stdout, inspect their own argv, and potentially emit a targeted nonce marker; duplicate-marker detection rejects the tested forgery, but this is not cryptographic proof against a malicious in-process test. Candidate test suites are not independently trusted acceptance tests. Command outputs can carry arbitrary secrets and are not comprehensively redacted; never inject real secrets into candidate containers. Image tags are mutable; pin/attest the trusted image in production. A privileged operator can truncate/recompute the local chain; use external signed checkpoints. Local hooks are bypassable, MCP does not intercept other tools, and CI enforcement requires protected branch settings. No live container test has been observed in this environment.
